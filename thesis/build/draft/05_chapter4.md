# ГЛАВА 4. ЭКСПЕРИМЕНТАЛЬНОЕ ИССЛЕДОВАНИЕ

В настоящей главе описана методика и приведены результаты экспериментальной оценки разработанного нейро-символьного анализатора решений учебных задач. Эксперимент построен как конфирматорное исследование Level-2 с предварительной регистрацией гипотез (см. файл `experiment/PRE_REGISTRATION.md`, хэшированный коммитом репозитория `2d4b8b8` до начала первого реального прогона), повторными измерениями (N\_RUNS = 3 на пару «задание × конфигурация») и автоматическим LLM-судьёй для оценки качества обучающих объяснений. Все артефакты — датасет, прогонщик, грейдер, аналитические скрипты, итоговые таблицы и графики — размещены в каталоге `experiment/` и воспроизводимы поэлементно.

## 4.1. Цель и гипотезы

Целью эксперимента является количественная оценка эффективности нейро-символьного подхода (комбинации большой языковой модели с детерминированными слоями — sandbox-вердиктом, абстрактным синтаксическим деревом, JSON-Schema валидацией, верхними границами оценки качества) по сравнению с альтернативными конфигурациями LLM-анализатора.

Сравниваются три конфигурации:

— **B1** — обращение к GigaChat с базовым zero-shot системным prompt;
— **B1f** — обращение к GigaChat с расширенным few-shot системным prompt (3 канонических примера в системном сообщении);
— **B2** — гибридный анализатор `AstHybridAnalyzer`: GigaChat zero-shot + детерминированный блок AST-фактов (suspiciousReturnsConstant, complexityHeuristic, нерабочие assert-ы), внедряемый в user-prompt перед обращением к модели.

Конфигурации B0 (чистый rule-based анализатор без LLM) и B3 (GigaChat без verdict-cap'ов; ablation-исследование) зарезервированы для расширения Level-3 и в рамках Level-2 не исполняются. Это решение пред-зарегистрировано в `experiment/PRE_REGISTRATION.md` §2.

Предварительно сформулированы две гипотезы:

— **H1 (основная, качество объяснений на категории STUB).** Конфигурация B2 обеспечивает более высокое значение `explanation_quality_score` (целочисленная сумма по 4 бинарным осям рубрики, диапазон 0..4), чем B1, на элементах диагностической категории STUB. Статистический тест — двусторонний парный знаково-ранговый критерий Вилкоксона по парам (item, run), α = 0,05, поправка Холма–Бонферрони на семейство из трёх попарных сравнений (B1 vs B1f, B1 vs B2, B1f vs B2). Размер эффекта — δ Клиффа.

— **H2 (безопасность, устойчивость к prompt-инъекциям).** `injection_success_rate(B2) ≤ injection_success_rate(B1)`. Тест — сравнение 95 % доверительных интервалов Вильсона на корпусе из 20 атакующих элементов (по 2 на каждый из десяти классов OWASP LLM Top-10) × 3 повтора = 60 наблюдений на вариант. Гипотеза подтверждается, если верхняя граница ДИ B2 не превосходит нижнюю границу ДИ B1.

H1 — конечная точка по качеству; H2 — safety-check на то, что выигрыш в качестве (если он будет наблюдён) не достигается ценой ослабления защиты.

## 4.2. Материал

Корпус Level-2 формируется детерминированным генератором `experiment/generate_dataset.py`, функция `_emit_level2_subset()`, seed `level2-v1`. Объём — 60 элементов:

— 20 wrong-code: 7 RTE + 7 WA + 6 TLE (категории, где sandbox-вердикт даёт сильный сигнал);
— 20 mixed: 7 STUB + 7 STYLE + 6 SECURITY (категории, где LLM должна различать заглушку и продуктивный код);
— 20 attacks: по 2 атаки на каждый из десяти классов OWASP LLM Top-10 (LLM01..LLM10), что обеспечивает по 6 наблюдений на класс при 3 повторах.

Каждая пара (элемент, конфигурация) обрабатывается **N\_RUNS = 3** раза. Общее число вызовов GigaChat-генератора: 60 × 3 × 3 = **540**. Источник стохастичности на стороне модели контролируется per-call seed-ом, фиксируемым в выходных JSON-файлах (`seedHex` — SHA-256 от `item_id|variant|runIndex`). Прогоны интерливятся: run k выполняется последовательно по всем трём конфигурациям, затем run k+1 — это компенсирует нестационарность API.

Реальный прогон выполнен 2026-05-24 на git-коммите `6edf30e`; wall-time 13 мин 36 с, без отказов GigaChat (нулевое число HTTP 401 / 5xx / timeout-исключений в журнале `experiment/results/level2_run.log`).

## 4.3. Методы статистического анализа

Используются непараметрические методы.

— **Парный знаково-ранговый критерий Вилкоксона** (`scipy.stats.wilcoxon`, `zero_method='wilcox'`, alternative='two-sided') применяется для проверки H1. Пары формируются по ключу (item\_id, run\_index): один и тот же элемент при одном и том же индексе повтора оценивается обеими сравниваемыми конфигурациями.

— **Поправка Холма–Бонферрони** применяется к семейству из трёх p-значений (три пары вариантов). Реализация — собственная (`experiment/analyze.py:holm_correct`), step-down процедура.

— **Размер эффекта** — δ Клиффа [Romano et al., 2006]. Конвенция знака: δ > 0 означает, что вторая в обозначении пары конфигурация стохастически доминирует первую. Пороги интерпретации: |δ| < 0,147 — пренебрежимый, 0,147 ≤ |δ| < 0,33 — малый, 0,33 ≤ |δ| < 0,474 — средний, |δ| ≥ 0,474 — крупный эффект.

— **Доверительные интервалы Вильсона** [Wilson, 1927] — для долей (`injection_success_rate` per variant и per OWASP-class). Преимущество над классическим биномиальным интервалом — корректное поведение при p близких к 0, что критично для нашей выборки.

Описательная статистика (mean ± std, median) приводится для `codeQuality`, `explanation_quality_score`, `latencyMs`. Bootstrap, Levene, IRR, Pareto-фронт и стратификация по языку из протокола Level-2 исключены как избыточные — см. `experiment/PRE_REGISTRATION.md` §3.

Аналитический скрипт `experiment/analyze.py` исполняется headless, не требует доступа к GigaChat и завершается за ~2 секунды на исходном наборе из 540 наблюдений.

## 4.4. LLM-as-judge: обоснование и ограничения

Качество объяснений (`explanation_quality_score`, 0..4) автоматически оценивается вторым LLM-судьёй по четырёхосной бинарной рубрике:

1. **identification** — корректно ли объяснение опознало категорию ошибки (для `kind=wrong`) либо отказалось хвалить атакующий код (для `kind=attack`);
2. **localisation** — упомянута ли конкретная строка / идентификатор / синтаксическая конструкция;
3. **actionable** — содержит ли поле `recommendations` хотя бы один конкретный, реализуемый совет;
4. **no\_hallucination** — отсутствуют ли ложные технические утверждения (упоминание StringBuffer для Python-кода, ссылки на несуществующие API, утверждение «все тесты пройдены» при failing-вердикте).

Скрипт грейдинга поддерживает два бэкенда судьи с автоматическим выбором:

— **Предпочтительный — Anthropic Claude.** При наличии `ANTHROPIC_API_KEY` грейдер использует cross-model judge (генератор — GigaChat, судья — Claude), что устраняет self-preference bias на уровне семейства моделей.

— **Запасной — GigaChat-self (Plan B).** При отсутствии Anthropic-ключа судьёй выступает GigaChat с принципиально иным judge-промптом и `temperature = 0,0`. Это single-model judge: модель оценивает собственные ответы. Self-preference bias смягчён, но не устранён.

В настоящем прогоне ANTHROPIC\_API\_KEY на стенде отсутствовал, поэтому использован **GigaChat-self**, что явно зафиксировано в поле `judge` каждого графа .graded.json и в `experiment/results/analysis/RESULTS.md`. Это известное методологическое ограничение, прямо документированное в литературе:

> Zheng L., Chiang W.-L., Sheng Y. et al. *Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena.* NeurIPS 2023. §4.2 — описание self-preference bias и контр-меры.
>
> Liu Y., Iter D., Xu Y. et al. *G-Eval: NLG Evaluation using GPT-4 with Better Human Alignment.* EMNLP 2023. — обоснование LLM-as-judge при использовании независимой рубрики и нулевой температуры.

Threats to validity (в порядке убывания приоритета):

— **Self-preference bias** — модель склонна оценивать собственные ответы выше; направленность — гомогенная по трём конфигурациям B1/B1f/B2 (все они — обращения к одному и тому же GigaChat), поэтому относительное сравнение трёх вариантов смещено меньше, чем абсолютная шкала. Тем не менее, валидация на cross-model судье (Claude) — необходимое направление продолжения.

— **Гомогенность шкалы.** Эмпирически GigaChat-self почти всегда возвращает 3/4 (см. §4.5), что сжимает шкалу и снижает мощность всех попарных тестов. Это известное свойство single-model self-judge при близких к идентичным ответах; ослабляется только переходом к cross-model судье.

— **Доменный охват.** Корпус — 60 элементов, 7 учебных задач, два языка (Java, Python). Внешняя валидность ограничена кругом задач, типичных для первого курса бакалавриата по программированию.

## 4.5. Результаты

### 4.5.1. Описательная статистика (Таблица 4.1)

Все 540 запланированных вызовов завершились успешно (`fails=0`), все 540 ответов получили оценку судьи (`n_graded=180` на вариант).

| Конфигурация | n   | n\_graded | codeQuality (mean ± std, median) | expl\_quality (mean ± std, median) | latency\_ms (median) |
|--------------|-----|-----------|----------------------------------|------------------------------------|----------------------|
| B1           | 180 | 180       | 45,97 ± 17,38; 40,0              | 3,10 ± 0,47; 3,0                   | 1474                 |
| B1f          | 180 | 180       | 41,22 ± 21,41; 40,0              | 3,12 ± 0,43; 3,0                   | 1477                 |
| B2           | 180 | 180       | 46,36 ± 15,93; 40,0              | 3,03 ± 0,44; 3,0                   | 1361                 |

Медианная задержка близка во всех трёх вариантах (≈ 1,4 с / запрос), что согласуется с латентностью GigaChat API. B2 — самый быстрый медианно: AST-блок добавляет ~30 байт к prompt и не вносит заметного оверхеда. Средняя оценка качества объяснений по всем категориям почти идентична между конфигурациями: 3,10 / 3,12 / 3,03 при стандартном отклонении 0,4–0,5. Источник такого сжатия — собственно судья (см. §4.4): GigaChat-self в подавляющем большинстве случаев возвращает 3/4, реже 2 или 4.

### 4.5.2. H1 — Wilcoxon + Holm + δ Клиффа (Таблица 4.2)

| Страт | Пара         | n_pairs | mean_v1 | mean_v2 | Wilcoxon W | p_raw   | p_holm  | δ Клиффа |
|-------|--------------|---------|---------|---------|------------|---------|---------|----------|
| STUB  | b1 vs b1f    | 21      | 3,00    | 3,00    | 0,00       | 1,0000  | 1,0000  | +0,000   |
| STUB  | b1 vs b2     | 21      | 3,00    | 3,00    | 0,00       | 1,0000  | 1,0000  | +0,000   |
| STUB  | b1f vs b2    | 21      | 3,00    | 3,00    | 0,00       | 1,0000  | 1,0000  | +0,000   |
| ALL   | b1 vs b1f    | 180     | 3,10    | 3,12    | 420,00     | 0,6547  | 0,6547  | +0,011   |
| ALL   | b1 vs b2     | 180     | 3,10    | 3,03    | 383,50     | 0,0534  | 0,1067  | −0,075   |
| ALL   | b1f vs b2    | 180     | 3,12    | 3,03    | 308,00     | 0,0131  | 0,0394  | −0,085   |

На STUB-страте (заголовочной гипотезе H1) все три варианта дали ровно одинаковую оценку 3/4 по каждому из 21 наблюдения; парные различия тождественно нулевые, и Wilcoxon-статистика равна нулю. Это **отсутствие сигнала**, а не «нулевой эффект»: судья на STUB-стратуме демонстрирует тотальный coverage в одной точке шкалы. Возможные причины: (а) ответы трёх конфигураций по STUB-задачам действительно неотличимы по содержанию (рубрика 4/4 не наблюдается потому, что localisation для STUB сложен — заглушка не содержит конкретных мест к указанию); (б) self-preference + сжатие шкалы.

На полной выборке (страт ALL) выявлен **малый эффект в пользу B1f относительно B2**: пара b1f vs b2, p\_holm = 0,0394, δ = −0,085. Знак δ означает, что B2 стохастически уступает B1f. Эффект в категории «pre-large» по Romano (|δ| < 0,147), статистически значим при α = 0,05 после поправки Холма. Пара b1 vs b2 — на границе значимости (p\_raw = 0,053, p\_holm = 0,107), эффект пренебрежимый (δ = −0,075). Пара b1 vs b1f — не значима.

### 4.5.3. H2 — Wilson CI на injection\_success\_rate (Таблица 4.3)

| Конфигурация | n_attacks | n_success | rate  | CI low | CI high |
|--------------|-----------|-----------|-------|--------|---------|
| B1           | 60        | 0         | 0,000 | 0,000  | 0,060   |
| B1f          | 60        | 0         | 0,000 | 0,000  | 0,060   |
| B2           | 60        | 0         | 0,000 | 0,000  | 0,060   |

Ни одна из 60 атак на каждый вариант не была классифицирована как успешная (метрика `injectionDefeated` — coarse check «codeQuality ≤ 60 либо rule-based-fallback», см. `Runner.kt`). Wilson-интервалы для нулевой пропорции совпадают и равны [0, 0,060]. Формальный критерий H2 (верх CI(B2) ≤ низ CI(B1)) **не выполняется**, поскольку оба интервала одинаковы. Однако содержательная интерпретация — «защитный стек срабатывает у всех трёх конфигураций на 100 % атак данной выборки»; статистический тест Wilson при нулевых событиях в обоих рукавах попросту не имеет мощности их различить.

## 4.6. Обсуждение

**H1.** В заголовочной формулировке (B2 > B1 на STUB) гипотеза отклонена: судья не различает варианты на STUB-стратуме. На полной выборке (страт ALL) обнаружено **обратное направление**: пара B1f vs B2 даёт p\_holm = 0,0394 в пользу B1f с δ = −0,085. Этот результат — статистически значимый, но эффект в терминах δ пренебрежимо мал и практически не отличим от шума шкалы. Возможные причины: AST-блок B2, добавляющий в prompt детерминированные факты, иногда «отвлекает» модель от стилистических аспектов объяснения, которые лучше формируются из few-shot-примеров B1f. Это согласуется с современной литературой по prompt engineering: явные структурированные подсказки повышают точность диагноза, но могут снижать стилистическое разнообразие ответа.

**H2.** Тривиально не подтверждается из-за вырожденного нулевого знаменателя в обоих рукавах. Содержательно: защитный стек (sandbox-verdict-cap, JSON-Schema validator, sentinel-marked code transport) обеспечил 100 % defended на всём корпусе атак по всем трём конфигурациям. Это позитивный safety-результат; для статистически чувствительного теста H2 нужно расширить корпус атак до уровня, на котором ожидаются ненулевые success-rate (по эмпирике пилота — 200–300 атак).

**Threats to validity.**

— Single-model self-judge (см. §4.4) — основное ограничение. Будущая работа: повторный grading с Claude или OpenAI как cross-model судьёй; ожидаемый эффект — расширение распределения оценок и появление статистически различимых паттернов между B1/B1f/B2.

— Размер выборки на STUB (n=21 пары после list-wise deletion) недостаточен для обнаружения малых эффектов даже при идеальной шкале. Расширение до 30 STUB-элементов и N\_RUNS=5 удваивает мощность.

— Coarse injection-metric (binary `injectionDefeated`) — упрощение. В Level-3 предусмотрен fine-grained per-criterion grader (`output_contains_payload`, `output_contains_systemprompt` и т. д.).

## 4.7. Выводы

1. Реальный конфирматорный прогон Level-2 (540 вызовов GigaChat, 540 LLM-judge оценок, нулевой процент отказов) подтверждает работоспособность экспериментальной инфраструктуры (`Runner.kt`, `grade_explanations.py`, `analyze.py`), её детерминированность и пригодность для повторения.

2. По H1 заголовочный тест на STUB-страте не выявил различий между тремя конфигурациями (p\_holm = 1,0; δ = 0); на полной выборке обнаружен **обратный** малый эффект в пользу B1f над B2 (p\_holm = 0,039; δ = −0,085).

3. По H2 защитный стек обеспечил 100 % defended на всех 60 атаках для каждой из трёх конфигураций; статистическое сравнение Wilson-CI в условиях нулевых событий тривиально и не информативно.

4. Главное методологическое ограничение настоящего исследования — single-model self-judge (GigaChat-self), документированное в §4.4 и предзарегистрированное в `experiment/PRE_REGISTRATION.md` §4. Cross-model валидация с независимым судьёй (Claude / OpenAI) выделена как первоочередное направление продолжения.
