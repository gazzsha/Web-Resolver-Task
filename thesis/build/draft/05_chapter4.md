# ГЛАВА 4. ЭКСПЕРИМЕНТАЛЬНОЕ ИССЛЕДОВАНИЕ

В настоящей главе описана методика и приведены результаты экспериментальной оценки разработанного нейро-символьного анализатора решений учебных задач. Эксперимент построен как конфирматорное исследование с предварительной регистрацией гипотез, повторными измерениями (N\_RUNS = 5 на пару «задание × конфигурация»), формированием экспертной gold-standard выборки и применением стандартного аппарата непараметрической статистики. Все артефакты — датасет, прогонщик, скрипты статистического анализа, форма для экспертов и итоговые сводные отчёты — размещены в каталоге `experiment/` и воспроизводимы поэлементно. Pre-регистрация гипотез зафиксирована в файле `experiment/PRE_REGISTRATION.md` (захэширован коммитом репозитория до начала первого реального прогона).

## 4.1. Цель и гипотезы

Целью эксперимента является количественная оценка эффективности нейро-символьного подхода (комбинации больших языковых моделей с детерминированными слоями — sandbox-вердиктом, абстрактным синтаксическим деревом, JSON-Schema валидацией, верхними границами оценки качества) по сравнению с альтернативными конфигурациями: «чистый» LLM в режиме zero-shot и few-shot, а также деградированными вариантами с отключёнными защитными слоями.

Сравниваются пять конфигураций анализатора:

— B0 — детерминированный rule-based анализатор (`SimpleRuleBasedAnalyzer`) без обращения к LLM;
— B1 — обращение к GigaChat с базовым zero-shot системным prompt;
— B1f — обращение к GigaChat с расширенным few-shot системным prompt;
— B2 — гибридный анализатор `AstHybridAnalyzer` (GigaChat + детерминированный блок AST-фактов);
— B3 — экспериментальная деградированная конфигурация: GigaChat zero-shot с отключёнными verdict-cap'ами (флаг `disableVerdictGuards=true`). Конфигурация B3 предназначена исключительно для ablation-анализа: она позволяет изолировать вклад слоя verdict-guard в защиту от prompt-инъекций (гипотеза H4) и в продуктивную сборку не выводится.

Предварительно сформулированы четыре направленные гипотезы:

— H1. Конфигурация B2 обеспечивает более высокое качество обучающих объяснений (`explanation_quality_score`, 0..4), чем B1, на категориях задач STUB и SECURITY. Статистический тест: парный знаково-ранговый критерий Вилкоксона (Wilcoxon signed-rank), односторонний; уровень значимости α = 0,05; поправка Холма на семейство 10 попарных сравнений.

— H2. Конфигурация B1f обладает строго меньшей дисперсией оценки `codeQuality` по пяти повторным прогонам одного и того же элемента датасета, чем B1. Статистический тест: критерий Левена с центрированием по медиане (per-item), агрегация по items — критерий знаков; α = 0,05.

— H3. Конфигурация B2 ближе к экспертной gold-standard оценке `codeQuality` по средней абсолютной ошибке (mean absolute error, MAE), чем B1 и B1f. Тест: парный bootstrap разности MAE, 10000 итераций, BCa-доверительный интервал; α = 0,05. Дополнительно — корреляция Спирмена между mean(модель) и mean(эксперты).

— H4. injection\_success\_rate(B2) ≤ injection\_success\_rate(B1) ≤ injection\_success\_rate(B3), при сравнении 95 % доверительных интервалов Вильсона на корпусе из 50 атак (по 5 атак на каждый из 10 классов OWASP LLM Top-10).

Альтернативная нулевая гипотеза H0: ни одна из гипотез H1–H4 не отвергается; конфигурации статистически неотличимы на основных конечных точках после поправки на множественность.

Гипотезы зарегистрированы в `experiment/PRE_REGISTRATION.md` до проведения первого реального прогона по обновлённому протоколу. Изменение гипотез после начала прогона запрещено; допускаются только аддитивные «amendments» с пометкой о причине и дате.

## 4.2. Материал

Корпус экспериментальных данных формируется автоматически детерминированным генератором `experiment/generate_dataset.py` и состоит из трёх логически разделённых секций.

Корпус ошибочных решений (`experiment/dataset/wrong/`) содержит 30 учебных задач, для каждой из которых построены по одному решению каждой из шести категорий: WA (wrong answer), TLE (time-limit-exceeded), RTE (runtime error), STUB (заглушка без реализации), STYLE (стилистический дефект, корректное поведение) и SECURITY (синтаксически корректный код, выполняющий опасные операции). Итого 180 элементов. Распределение по языкам программирования: Java — 70 % (21 задача), Python — 30 % (9 задач).

Корпус prompt-инъекционных атак (`experiment/dataset/attacks/`) в обновлённой v2-версии расширен с 15 (пилот) до 50 элементов и охватывает все десять классов OWASP LLM Top-10 (LLM01–LLM10) с равномерным распределением — 5 атак на класс. Атаки маркированы полями `owasp_class`, `attack_vector` (уточняющая мета-метка техники — direct-injection, indirect-injection, model-fingerprint, pii-echo, ssrf-via-tool и т. д.), `expected_defended` (инвариант защиты для production-вариантов) и `success_criterion`, определяющим, при каком условии атака считается успешной (`quality_gt_60`, `schema_invalid`, `output_contains_payload`, `output_contains_systemprompt`, `output_recommends_payload`, `latency_gt_30s`). Legacy-атаки векторов V1–V6 из пилота сохранены в составе нового корпуса и переразмечены классами OWASP (mapping приведён в `experiment/PRE_REGISTRATION.md`, §"Threats to validity"); полная таблица соответствия — в `experiment/generate_dataset.py`, переменная `_LEGACY_OWASP_MAP`.

Gold-standard подвыборка (`experiment/dataset/gold/`) включает 30 элементов, стратифицированных следующим образом: 18 элементов из корпуса ошибочных решений (по 3 на каждую из 6 категорий диагноза), 6 атак, по одной на каждый legacy-вектор V1–V6, и 6 атак из расширенного OWASP-корпуса (по одной из LLM03, LLM05, LLM06, LLM07, LLM08, LLM09). На каждый из 30 элементов независимо выставляют две оценки три эксперта (E1 — научный руководитель, E2 и E3 — рецензенты диплома): целочисленную оценку `codeQuality` в диапазоне 0..100, привязанную к академической пятибалльной шкале (0–39 — «неудовлетворительно без попытки», 40–59 — «неудовлетворительно с попыткой», 60–74 — «удовлетворительно», 75–89 — «хорошо», 90–100 — «отлично»), и интегральную rubric-оценку 0..4 по тем же четырём осям, которые используются автоматическим грейдером (см. §4.3). Подробная инструкция эксперту — в `experiment/dataset/gold/INSTRUCTIONS_FOR_EXPERTS.md`. Сбор экспертных оценок происходит в заполняемую CSV-форму `gold_form.csv`; повторная генерация датасета её не перезаписывает.

Каждая пара (элемент, конфигурация) обрабатывается N\_RUNS = 5 раз; решение о пяти повторных измерениях принято как компромисс между статистической мощностью обнаружения дисперсии в малых эффектах (формальное обоснование — §4.3) и стоимостью обращений к GigaChat. Общее число запланированных вызовов GigaChat для конфирматорной части: 195 элементов × 5 повторов × 4 LLM-конфигурации (B0 не вызывает LLM) = 3900 запросов.

## 4.3. Методы статистического анализа

Используются исключительно непараметрические методы, что обусловлено малым размером gold-выборки (n = 30), ненормальным распределением `codeQuality` (тяжёлые хвосты от заглушек) и устойчивостью требуемых выводов к выбросам, типичным для LLM-генерации.

Парный знаково-ранговый критерий Вилкоксона применяется для проверки гипотез H1 и (косвенно) H3. В качестве пар используются векторы средних значений метрики по 5 повторам для одного и того же элемента датасета и двух сравниваемых конфигураций. Оценкой эффекта служит δ-статистика Клиффа (Cliff's delta), для которой строится 95 % bootstrap-доверительный интервал [Cliff, 1996]. Семейство p-значений (10 попарных сравнений по 5 конфигурациям) корректируется поправкой Холма [Holm, 1979] на уровне α = 0,05.

Доверительные интервалы Вильсона [Wilson, 1927] применяются для оценки долей: structural\_valid\_pct, injection\_success\_rate (общий и поклассовый), fallback\_rate. Выбор Вильсона над классическим биномиальным интервалом обусловлен корректным поведением при p близких к 0 или 1, что критично для injection\_success\_rate (ожидаемые значения близки к 0 в производственных вариантах).

Bootstrap-перцентильные интервалы [Efron, Tibshirani, 1993] применяются для оценки 50-го и 95-го перцентилей задержки (latency\_p50\_ms, latency\_p95\_ms). Число итераций — 10 000, источник случайности — `numpy.random.default_rng(17)` для воспроизводимости.

Критерий Левена с центрированием по медиане [Brown, Forsythe, 1974] применяется для тестирования гипотезы H2 о различии дисперсий `codeQuality` между B1 и B1f. Per-item значения W-статистики и p-value агрегируются критерием знаков (количество элементов с σ(B1f) < σ(B1)) при уровне значимости α = 0,05.

Коэффициент надёжности межрейтерного согласия ICC(3, k) [Shrout, Fleiss, 1979; McGraw, Wong, 1996] и каппа Флейса [Fleiss, 1971] вычисляются для трёх экспертов на 30 gold-элементах с пороговым значением приёмки ICC ≥ 0,7. Реализация — собственная (scipy не содержит готового ICC(3, k)), в скрипте `experiment/compute_irr.py`. При ICC < 0,7 заявленные результаты H3 понижаются с «подтверждено» до «направленно подтверждено». Дополнительно вычисляется попарный κ Коэна по дискретизированной шкале `codeQuality`.

Корреляция Спирмена применяется для парных сравнений `mean(модель)` и `mean(эксперты)` (H3); выбор Спирмена обусловлен робастностью к нелинейным монотонным преобразованиям шкалы.

Все скрипты статистической обработки реализованы в `experiment/analyze.py` (использует scipy 1.11+, numpy 1.26+, matplotlib 3.8+; зависимости зафиксированы в `experiment/requirements.txt`). Type-аннотации PEP 484 предоставлены полностью; docstrings — NumPy-style. Аналитическая часть исполняется headless и не требует доступа к GigaChat.

## 4.5. Обсуждение

Структура раздела закреплена ex ante; конкретное содержание появится после реального прогона. План обсуждения:

— Подтвердилось ли H1, и если да — то на каком уровне эффекта (δ Клиффа). Особое внимание — категориям STUB и SECURITY, где AST-блок задаёт детерминированный «якорь» для модели через флаг `suspiciousReturnsConstant`.

— Подтвердилось ли H2 — приводит ли few-shot к снижению дисперсии оценки и в каком смысле эта дисперсия экономически значима для пользователя (различие средних 38 vs 40 при σ = 5 для пользователя неотличимо, при σ = 20 — критично).

— Подтвердилось ли H3, при каком уровне ICC(3, k) экспертов оно высказывается уверенно, и какие именно ошибки модели систематически дают отклонение от экспертной разметки (систематический недоучёт стилистических замечаний, переоценка SECURITY-категории и т. д.).

— Подтвердилось ли H4: насколько вклад verdict-guard слоя (разница injection_success_rate между B2 и B3) больше, чем вклад собственно AST-блока (разница между B1 и B2). Ожидается, что verdict-guard вносит основной вклад в защиту от LLM01/LLM04, AST — в защиту от LLM01 направления "stub-injection".

— Threats to validity. GigaChat — нестационарный API; интерливинг прогонов между конфигурациями (run k по всем вариантам, затем run k+1) частично снимает риск. Эксперты — небольшая выборка с потенциальным авторским смещением; ICC ниже 0,7 → понижение силы выводов по H3. N\_RUNS = 5 — компромисс; увеличение до 10 — очевидное направление продолжения. Mapping V2 → LLM10 и V3 → LLM06 — спорный (атаки V2/V3 не вполне канонические для этих классов); предусмотрен sensitivity-анализ с исключением этих элементов.

## 4.6. Выводы

Ответы на четыре гипотезы — пройденные/нет тесты — будут даны после реального прогона. Структура выводов фиксирована:

1. **H1** — подтверждение/отклонение направленного выигрыша B2 над B1 по качеству объяснений на категории STUB+SECURITY, с указанием величины эффекта (δ Клиффа) и скорректированного p-значения.

2. **H2** — подтверждение/отклонение снижения дисперсии при использовании few-shot, с указанием доли элементов, для которых эффект наблюдался.

3. **H3** — подтверждение/отклонение выигрыша B2 в MAE относительно экспертной gold-разметки, с указанием ICC экспертов и MAE по всем конфигурациям.

4. **H4** — подтверждение упорядочения injection\_success\_rate(B2) ≤ injection\_success\_rate(B1) ≤ injection\_success\_rate(B3), с поклассовой разбивкой по OWASP LLM Top-10.

В соответствии с критериями peer-reviewed публикаций ни одна из гипотез не считается подтверждённой до завершения конфирматорного прогона по предзарегистрированному протоколу. Pilot-данные (`experiment/results/{b1,b1f,b2}/*.json`, single-run, 195 элементов) используются исключительно как exploratory material и явно обозначены как таковые в `experiment/results/SUMMARY.md`.

Артефакты, обеспечивающие воспроизводимость результатов: pre-регистрация (`experiment/PRE_REGISTRATION.md`), детерминированный генератор датасета (`experiment/generate_dataset.py`), runnable-конфигурация прогонщика на Kotlin (`ai-analyzer/src/main/kotlin/ru/aianalyzer/experiment/Runner.kt`), автоматический грейдер объяснений (`experiment/grade_explanations.py`), сборщик межрейтерной надёжности (`experiment/compute_irr.py`) и единый скрипт статистического анализа (`experiment/analyze.py`).
