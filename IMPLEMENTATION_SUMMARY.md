# Implementation Summary - Chapter 2: System Design

## Что было реализовано

В соответствии с планом диплома реализована **модульная сервис-ориентированная архитектура** системы для проверки программировочных задач с AI-анализом.

## Архитектурные компоненты

### 1. Sandbox Service (Модуль `sandbox`)

**Назначение:** Безопасное выполнение пользовательского кода

**Реализация:**
- `DockerSandboxService.kt` - основной сервис для выполнения кода
- `SandboxSecurityConfig.kt` - конфигурация безопасности
- `SandboxModels.kt` - модели данных

**Ключевые особенности:**
```kotlin
// Изоляция через Docker
- Контейнеры для каждого запуска
- Сеть отключена (--network=none)
- Файловая система read-only
- Capabilities сброшены

// Лимиты ресурсов
- CPU: 1 ядро
- Память: 256 MB
- Timeout: 5 секунд
```

**Поддерживаемые языки:** Java, Kotlin, Python

### 2. Worker Service (Модуль `worker`)

**Назначение:** Асинхронная обработка задач из очереди

**Реализация:**
- `WorkerService.kt` - оркестрация выполнения
- `WorkerKafkaListener.kt` - потребитель Kafka
- `WorkerResultPublisher.kt` - публикация результатов
- `WorkerModels.kt` - модели данных

**Функции:**
- Потребление задач из Kafka
- Оркестрация: Sandbox → Test Engine → Scenario Runner → AI
- Публикация результатов

**Масштабируемость:**
```yaml
# Docker Compose
worker:
  deploy:
    replicas: 3  # Горизонтальное масштабирование
```

### 3. AI Analyzer Module (Модуль `ai-analyzer`)

**Назначение:** Анализ кода и образовательная обратная связь

**Реализация:**
- `ChatGPTAnalyzer.kt` - AI анализ через ChatGPT
- `SimpleRuleBasedAnalyzer.kt` - правило-based анализ (fallback)
- `AIAnalyzerConfig.kt` - конфигурация

**Научная новизна - Гибридная проверка:**
```
Test Engine → Факт ошибки
     ↓
AI Module → Объяснение и рекомендации
     ↓
AST (опционально) → Структурное подтверждение
```

**Функции AI:**
- Оценка качества кода (0-100)
- Поиск проблем (BUG, CODE_SMELL, SECURITY, PERFORMANCE, STYLE)
- Персонализированные рекомендации
- Объяснение ошибок на естественном языке

### 4. Scenario Runner (Модуль `scenario-runner`)

**Назначение:** Проверка интерактивных задач с состоянием

**Реализация:**
- `DefaultScenarioRunnerImpl.kt` - реализация сценариев

**Уникальная особенность диплома:**
- Поддержка меню-ориентированных программ
- Многошаговые взаимодействия
- Валидация поведения (behavior flow)
- State-dependent тестирование

**Пример использования:**
```
Шаг 1: Выбор пункта меню → "1"
Шаг 2: Ввод данных → "5 3"
Шаг 3: Проверка состояния → "[STATE: RESULT]"
```

### 5. Test Engine (в `worker`)

**Назначение:** Запуск и валидация тестов

**Реализация:**
- `TestEngine.kt` - интерфейс
- `DefaultTestEngine.kt` - реализация

**Типы тестов:**
- Стандартные I/O тесты
- Кастомные checker'ы
- Сценарные тесты

### 6. Database Module (Модуль `db`)

**Назначение:** Хранение результатов и AI-анализа

**Реализация:**
- `TaskResultEntity.kt` - сущность результатов
- `AIAnalysisEntity.kt` - сущность AI-анализа
- `TaskResultRepository.kt` - репозиторий
- `AIAnalysisRepository.kt` - репозиторий

**Сущности:**
```sql
task_results:
- task_id, test_id, user_id

- test_results (JSONB)

ai_analysis:
```


### 8. Infrastructure

**Docker Compose:**
```yaml

  postgres      # База данных
  zookeeper     # Kafka dependency
  kafka         # Очередь задач
  main-app      # API Gateway
  worker        # Обработчик (scale: 3)
```

**Kafka Topics:**
- `task-execution` - задачи на выполнение

- `ai-analysis` - AI-запросы

## Безопасность (Критично для защиты)

### Реализованные меры безопасности:

1. **Изоляция кода**
   - Docker контейнеры
   - Сеть отключена
   - Read-only файловая система

2. **Лимиты ресурсов**
   ```kotlin
   CPU: 1.0 cores
   Memory: 256 MB (max 512 MB)
   Timeout: 5s (max 10s)
   ```

3. **Запрещенные операции**
   ```kotlin
   FORBIDDEN_PATTERNS = [
     "Socket", "ServerSocket",      // Сеть
     "FileWriter", "Files.write",   // Файлы
     "Runtime.getRuntime().exec",   // Процессы
     "System.exit",                 // Выход
     "Class.forName",               // Reflection
     ...
   ]
   ```

4. **Docker security options**
   ```
   --network=none
   --read-only
   --cap-drop=ALL
   --no-new-privileges
   ```

## Обоснование архитектуры (для диплома)

### Почему НЕ монолит:

1. ❌ Сложно масштабировать выполнение кода
2. ❌ Небезопасно (sandbox внутри общего процесса)
3. ❌ Тяжело расширять AI-модуль

### Почему сервис-ориентированная:

1. ✅ **Изоляция компонентов** - каждый сервис в своем процессе
2. ✅ **Независимое масштабирование** - workers scale independently
3. ✅ **Безопасность** - Docker isolation
4. ✅ **Гибкость** - легко добавить новые языки
5. ✅ **Расширяемость** - AI-модуль можно улучшать отдельно

### Формулировка для диплома:

> "В качестве архитектурного подхода выбрана модульная сервис-ориентированная архитектура, обеспечивающая независимость компонентов, масштабируемость и возможность интеграции интеллектуальных модулей анализа."

## Поток выполнения (Execution Flow)

```
1. Пользователь отправляет код
   ↓
2. API сохраняет решение
   ↓
3. Задача отправляется в Kafka очередь
   ↓
4. Worker получает задачу
   ↓
5. Код запускается в Sandbox (Docker)
   ↓
6. Test Engine выполняет тесты
   ↓
7. Scenario Runner (если нужно) выполняет сценарии
   ↓
8. AI Module анализирует результаты
   ↓
9. Результаты сохраняются в БД
   ↓
10. Ответ возвращается пользователю
```

## Научная новизна

### Гибридная проверка:

1. **Test Engine** → Фактические ошибки (PASS/FAIL)
2. **AI Module** → Объяснение причин и рекомендации
3. **Scenario Runner** → Валидация поведения

Это и есть **научная новизна** работы - комбинация автоматической проверки с AI-объяснениями для образовательных целей.

## Почему это правильное архитектурное решение

### ✔ Масштабируемость
- Workers можно горизонтально масштабировать
- Kafka буферизует пиковые нагрузки
- Sandbox контейнеры эфемерны

### ✔ Безопасность
- Docker обеспечивает сильную изоляцию
- Лимиты ресурсов предотвращают злоупотребления
- Сеть отключена в контейнерах

### ✔ Гибкость
- Легко добавить новые языки программирования
- Плагиновые AI провайдеры
- Различные стратегии выполнения

### ✔ Расширяемость
- AI-модуль можно улучшать отдельно
- Новые типы тестов добавляются легко
- Поддержка кастомных checker'ов

### ✔ Поддержка сложных задач
- Scenario Runner для интерактивных задач
- State-dependent валидация
- Многошаговое тестирование
